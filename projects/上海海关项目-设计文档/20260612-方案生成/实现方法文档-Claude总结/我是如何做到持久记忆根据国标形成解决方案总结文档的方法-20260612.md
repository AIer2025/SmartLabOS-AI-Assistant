## 一、我是如何做到「持久记忆」的

我并非靠对话上下文记忆（那会随会话结束而丢失），而是靠一套**基于文件的记忆系统**，目录在：

```
C:\Users\littl\.claude\projects\c--TestClaude-SmartLabOS-AI-Assistant\memory\
```

机制：

1. **每条记忆 = 一个 Markdown 文件**，带 frontmatter（`name` / `description` / `type`），正文写明事实、原因（Why）与如何应用（How to apply）。
2. **`MEMORY.md` 是索引**：每条记忆在此留一行指针。**这个索引会在我每次新会话启动时自动载入到我的系统提示中**，所以我一进入项目就"看见"这些记忆的标题与摘要；需要细节时再打开对应文件。
3. 针对你这次的要求，我已写入一条记忆文件 **`gb-standard-to-solution.md`**（类型 `feedback`，即"用户给我的工作约定"），内容是：

   > **当用户给出一个 GB/国标检测标准的 MD（通常是 8.1&8.2 或 7.1&7.2 的"提取&净化"前处理流程）并要求"根据国标形成解决方案"时，按 `1.html` 的方法产出一份独立的 HTML SmartLabOS 前处理解决方案。**

   并在 `MEMORY.md` 索引中加了一行指针。

**结果：下次你再开新对话，只要给我国标 MD + 说"根据国标形成解决方案"，我会自动按本方法执行，无需你重新解释。** 若以后规则有变（比如换平台、改耗时口径、改输出目录），告诉我，我会更新这条记忆文件。

> 小提示：你也可以随时让我"查看/修改记忆"。记忆文件是纯文本，你本人也可直接打开查看或编辑。

## 二、根据国标形成解决方案的标准方法（1.html 配方）

每次我都按以下 8 步，从国标 MD 生成一份与 `1.html` **同结构、同风格、同口径**的 HTML 方案。

### 第 0 步 · 数据底座（只做一次，复用）
- **模组库**：`references/01-modules/`（97 个模组，YAML-MD）。我据此建了一张校验用索引
  `projects/上海海关项目/_build/module-index.md`（每模组的 `cycle_time_sec`、上下料、量程、兼容平台），**用于计时与 ID 校验**。
- **平台库**：`references/02-platforms/`（PLT-800 / PLT-1200 / PLT-1400）。
- **托盘库**：`references/06-pallet/`。**工作站/解决方案库**：`references/03-workstation`、`04-solutions`。

### 第 1 步 · 拆解国标前处理流程
把国标"提取&净化"（8.1/8.2 或 7.1/7.2）的文字，拆成可由单个模组执行的**原子操作**（加液、涡旋、超声、离心、转移、SPE、浓缩、复溶、过滤、酶解、加盐、调 pH …）。

### 第 2 步 · 模组选型（**绝不编造**）
逐个原子操作映射到模组库里**真实存在**的模组，标注关键参数与选型依据。
> 铁律：**每个 `MOD-xxx` ID 必须在 `references/01-modules/` 中存在**（对照索引校验）。例如上一版方案四曾误用并不存在的 `MOD-CC-003`，我已剔除并替换为真实模组。

### 第 3 步 · 平台选型（位约束）
- 一个平台最多 **6 模组位 + 8 托盘**（PLT-1200/1400）；PLT-800 为 **3 位 + 4 托盘**。
- **大体积模组占多位**：50ml/高速离心模组（`MOD-LX-001/004/005`）**各占 3 位**；`MOD-JY-012`（八通道正压加液）**占 0 位**。
- 据各工站模组位需求择平台（功能密集段一般 PLT-1200）。

### 第 4 步 · 组建工作站 + 串联解决方案
模组搭载到平台 → 形成功能工作站；工作站按前处理顺序串联 → 完整样品制备产线 → 对接 LC-MS/MS。参照 `references/03-workstation`、`04-solutions` 的已验证范式。

### 第 5 步 · 处理耗时测算（**核心新增 · §7**）
- **公式**：每平台处理节拍 = Σ 该平台所载模组（`功能码 cycle_time_sec` + `上下料 60 s`）；解决方案总节拍 = Σ 各平台节拍。
- **通道数 = 2 的口径**：模组卡的 `cycle_time_sec` 与上下料 `60 s` 都是按**双通道（默认通量 = 2，一循环处理 2 个样品）**标定的
  （例：上下料 `60 s = 15 s × 2 通道 × 2 上下料`）。因此算出的是 **「2 样品/循环」的处理节拍，不是单样**；
  报告中明确标注"2 样/循环"，并给出 **单样均摊 = 数值 ÷ 2**。
- **长流程取值**：超声/酶解/离心等长步骤按**国标规定时长**取值并脚注（如 超声 20 min = 1200 s）；其余取模组卡 `cycle_time_sec` 原值。
- 附注：高并行模组（SPE 多柱、超声多工位）与工站流水重叠可使稳态通量高于单循环节拍。

### 第 6 步 · 诚实合规
- 与国标的硬件差距**如实标注**（如标准 −2 ℃ / 10000 r/min 离心，现有模组只到 1–2 ℃ / 8000 rpm → 标为偏差并给整改建议）。
- 价格一律回复"**请联系销售团队获取报价**"，不报数字。
- 全部参数引自 `references/`，不杜撰。

### 第 7 步 · 输出 HTML（10 章并集格式）
融合两套范例（4.1 合并版 + 4.2 分标准版）的**并集**，固定 10 章：
1. 项目概述与标准解读 2. 工艺流程拆解（Mermaid） 3. 平台选型（卡片+对比表） 4. 模组选型（含"位"列）
5. **工作站组成**（每站 grid2 双栏：左=搭载模组表+合计+托盘清单；右=SVG 平台俯视布局[大模组跨 3 位]+底部走线注+流程行；顶部图例标注占位规则）
6. 解决方案串联（Mermaid + 条款表） 7. **处理耗时测算**（逐工站表 + 总节拍表，2 样/循环 + 单样均摊）
8. 通量/合规/偏差 9. 公用工程与场地 10. 物料/托盘清单 + 商务说明
- 视觉：Mermaid 流程图 + SVG 平台布局；中文专业术语（QuEChERS、SPE、LC-MS/MS 等）保持原文。
- 每个国标输出一个独立 HTML（如 `projects/上海海关项目/1.html`～`8.html`）。

## 三、一句话总结

> **持久记忆** = 写进 `memory/` 文件 + `MEMORY.md` 索引（每次开会话自动载入）。
> **形成方案** = 按 `1.html` 的 8 步配方：拆国标 → 选真实模组 → 配平台（位约束）→ 组工站串方案 → 算耗时（通道数=2、2 样/循环、单样均摊）→ 诚实合规 → 输出 10 章 HTML。
