1. 项目定位：从「会话方式」到「服务化 API 调用」

本项目是 SmartLabOS 售前技术方案生成的第二代实现。第一代（DataMaintenance + Claude Code 会话方式）依赖人工在 CLI 里投喂指令文件、以 --permission-mode bypassPermissions 越权访问磁盘；本项目改为用 Anthropic 官方 C# SDK 直接调用 Messages API，把整条链路收敛进一个可部署、可审计、可并发的 Web 服务。

4. 处理特点

① 知识库接地，不允许编造

技术参数一律要求 read_kb_file 实读卡片；系统前缀只给索引（97 个模块的 ID/名称/分类）， 参数必须现读。模块 ID 再经目录校验过滤。价格类问题固定回复「请联系销售团队获取报价」。 阶段二用 project/ 前缀回读阶段一产物，并有溯源校验兜底。

② 人工闸门卡在关键处

模块选定的结果必须人工确认才能进入生成；生成阶段的提示词把已确认清单标为「强制选型范围」， 确有缺口只允许在文中说明，不得自行替换。

③ 长文档靠分片写，不赌单次输出

一份提案 HTML 约 17K tokens，超过任何单次输出的舒适区。工具集提供 write_output + append_output， 提示词明确要求「先写开头再分次追加，每次 4000–5000 字」，并说明理由——每多一轮就要重读一遍全部上下文。 实测 1.html 首写 10,255 字符 + 追加 9 次 = 70,169 字节，全程未触发截断。

④ 先自检，再自愈

自检：发请求前校验请求体（当前覆盖 cache_control 的 TTL 一致性），拼错的请求根本发不出去。
截断：stop=max_tokens 不再当作完成，回喂续写指令。
故障：过载/限流/网络/SSE 中途错误 → 指数退避重试；鉴权与 400 类错误立即失败不空等。

⑤ 产物即验收

阶段结束逐一核对预期文件是否落盘，缺失即判 failed 并指名缺哪几份。 前端产物区按类分组，解决方案 HTML 少于流程标准数时红色高亮「缺 N 份」。

⑥ 全过程可观测

每轮记录 in / out / cacheRead / cacheWrite / stop；运行日志实时落盘到项目目录， 文件头记录本次模型、档位、MaxTokens、轮数上限，事后可完整复盘。
